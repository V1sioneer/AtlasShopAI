# Выбор поставщика и оплата каталога

Актуальное поведение на 2 октября 2026 года.

## Каталог

Кнопка «Каталог» открывает выбор:

1. Поставщик 1 · TheGodShop.
2. Поставщик 2 · Aethel.

Все товары GET-каталогов сохраняют свои название, категорию, цену и остаток.
На момент проверки: TheGodShop — 14 товаров, Aethel — 20. Позиции без остатка
тоже видны. K12, Plus, Go и варианты гарантии не смешиваются и не подменяют
друг друга. При ошибке выбранного API бот не переключает покупку к другому
поставщику.

TheGodShop использует положительные ID, Aethel — отрицательные. В заказах
сохраняются supplier, supplier_order_ref и исходные условия цены. Цена Aethel
в USD переводится по AETHEL_USD_RUB_RATE=87 с округлением вверх до копейки.
Прежняя наценка 15% сохраняется. Курс задаётся по стоимости пополнения, это
не живой биржевой курс.

Дополнительно доступны поиск по названию/категории, фильтр «В наличии»,
избранное и обновление цены/остатка в карточке. Поиск/фильтр и избранное
хранятся в SQLite. Избранное показывает товары обоих поставщиков, отдельно
от фильтра поиска. Длинные условия выдаются файлом по кнопке в карточке.

## TheGodShop: закупка на деньги покупателя

Доступно для всех обычных товаров каталога и количества 1–99, при достаточном
остатке. Пополнять свой партнёрский баланс заранее не требуется.

При обычной наценке создаются два независимых счёта CryptoBot:

1. Сервисный сбор Atlas Shop = итоговая цена минус закупка.
2. Закупочная сумма — напрямую на партнёрский баланс TheGodShop.

Сначала показывается счёт сервисного сбора. После подтверждения точных ID,
RUB-суммы и payload показывается счёт поставщика. Его статус, сумма, ID и
метод проверяются отдельно. Только после подтверждения обоих платежей бот
закупает указанное количество и сохраняет выдачу.

Пример: Gemini 100 ₽ закупка + 15 ₽ сервисный сбор = 115 ₽. По действующему
GEMINI100 одна штука без наценки требует только один счёт поставщика на
100 ₽. При покупке нескольких штук купон скидкой покрывает одну штуку,
остальные оплачиваются с обычной наценкой. Сбор — валовая выручка магазина;
комиссия CryptoBot уменьшает прибыль.

Внутренний баланс покупателя не кредитуется и не списывается. Обычная
кнопка закупки с баланса для TheGodShop убрана; прежнее подтверждение
направляет к новой карточке. Данные платежей не попадают в таблицу
пополнений пользовательского баланса.

На этапе проверки созданы реальные НЕОПЛАЧЕННЫЕ счета: депозит TheGodShop
#15 на 80 ₽ (0.96 USDT), счёт сервисного сбора CryptoBot #65878255 на 15 ₽.
Ссылки не выдавались покупателям; никаких закупок и списаний не выполняли.

## Ошибки и поддержка

Повторные клики не создают новый набор счетов для того же запроса. Закупка
отправляется один раз после атомарного перехода состояния. Оплаченные
средства поставщика защищены от расходов на чужие заказы внутри бота.
Если оплачена только одна часть, истёк второй счёт, изменилась закупочная
цена или закончился товар, заказ сохраняется для поддержки. Неизвестный
результат закупки не повторяется автоматически.

Обычный безопасный повтор выдачи разрешён для подтверждённых ошибок,
при сохранённых цене и товаре. Автоматического внешнего возврата нет:
API поставщика его не описывает. /direct_refunded только отмечает уже
выполненный вручную возврат. Сумма должна равняться действительно оплаченным
частям: например, только сбор 15 ₽ или обе части 115 ₽. Команда не переводит
денег и не начисляет внутренний баланс.

Нельзя расходовать зарезервированные покупательские деньги в кабинете
поставщика вручную. Бот контролирует только собственные операции.

Админ-команды: /direct_stats, /direct_order ID, /direct_retry ID,
/direct_refunded ID СУММА ВОЗВРАТ_ВЫПОЛНЕН. Покупатель видит счета через
«Мои счета» и /direct_orders, полную успешную выдачу — в истории заказов.

## Aethel и другие виды заказов

Документация: https://mail-api.hvmforum.space/api/docs
Aethel покупает с общего USD-баланса владельца; покупательские счета не
описаны. Его товары пока покупаются с внутреннего баланса Atlas Shop при
достаточном балансе Aethel, который проверяется до списания у покупателя.
Нулевой баланс поставщика не приводит к списанию пользователя.

Steam и игровые внешние заказы в отдельном разделе сохраняют прежнюю
схему. Новая прямая оплата относится к товарам GET-каталога TheGodShop.

## Проверка и миграция

95 тестов, compileall и git diff --check прошли. Тесты покрывают раздельные
каталоги, все SKU, поиск/фильтр/избранное, доступ только владельца, пары
счетов, частичную оплату, несколько штук, купон на одну штуку, повторные
клики, ошибки платёжных данных, защиту средств и миграцию старых счетов.
Реальная оплаченная выдача по новой схеме ещё не выполнялась; подтверждены
API-каталоги, создание и статусы неоплаченных счетов. Полный платёжный
сценарий проверен имитацией HTTP/API.

Миграция добавляет поля сервисного сбора в supplier_checkouts, таблицы
catalog_preferences и favorite_products. Для старых промосчетов сбор 0 и
margin_paid=true, прежняя выдача продолжается. Ключи находятся в закрытом
.env и локальной заметке Credentials, в GitHub не добавляются.
