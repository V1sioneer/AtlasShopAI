# TGShopBot — Telegram-бот витрина

Telegram-бот для перепродажи цифровых товаров, ИИ-подписок, пополнения Steam и игр через Partner API магазина [thegodapishop.xyz](https://thegodapishop.xyz).

## Возможности

- 🛒 **Каталог по категориям** — подписки на нейросети (ChatGPT, Claude, Gemini, Perplexity) и медиа-сервисы (Spotify, CapCut, Duolingo)
- 🎮 **Steam** — пополнение кошелька
- 🎮 **Игры** — покупка по variation_id
- 💰 **Баланс** — внутренний баланс пользователей
- 💳 **Платежные шлюзы** — оплата банковскими картами, СБП и через CryptoBot
- 📜 **История** — все заказы с пагинацией
- 👑 **Админ-панель** — управление балансами, депозитами, рассылки

## Быстрый старт

### 1. Клонирование и настройка

```bash
git clone <repo>
cd TGShopBot
cp .env.example .env
```

Заполните `.env`:

| Переменная | Описание |
|---|---|
| `BOT_TOKEN` | Токен Telegram-бота от @BotFather |
| `PARTNER_API_KEY` | Ключ партнёра (PRTNR-...) |
| `PARTNER_API_BASE` | URL API (по умолчанию https://api.thegodapishop.xyz) |
| `DATABASE_URL` | Строка подключения к БД |
| `MARKUP_PERCENT` | Наценка в % (по умолчанию 15) |
| `ADMIN_IDS` | Telegram ID администраторов через запятую |
| `LOG_LEVEL` | Уровень логирования (INFO/DEBUG) |
| `RATE_LIMIT_PER_SEC` | Лимит запросов к API/сек (по умолчанию 8) |
| `CRYPTOBOT_TOKEN` | Токен из [@CryptoBot](https://t.me/CryptoBot) -> Crypto Pay -> Create App (опционально) |
| `YOOKASSA_SHOP_ID` | Идентификатор магазина ЮKassa для оплаты картами/СБП (опционально) |
| `YOOKASSA_SECRET_KEY` | Секретный ключ ЮKassa (опционально) |

### 2. Запуск через Docker

```bash
docker-compose up -d --build
```

### 3. Запуск локально

```bash
pip install -r requirements.txt
python -m bot.main
```

## Бизнес-логика

### Ценообразование
- Цена пользователя = цена партнёра × (1 + MARKUP_PERCENT/100), округление вверх до 1 ₽

### Промокоды на товар без наценки
- `/promo_create КОД ID_ТОВАРА ЛИМИТ` (администратор) создаёт акцию: первые `ЛИМИТ` пользователей получают купон на одну штуку указанного товара по актуальной закупочной цене. Общая наценка магазина не меняется.
- Пользователь активирует купон через `/promo КОД`, кнопку «🎟 Промокод» или ссылку `https://t.me/AtlasShopAI_bot?start=promo_КОД`. Один купон на Telegram ID в каждой акции, без срока истечения.
- Это скидка при покупке, а не деньги на баланс. В заказе из нескольких штук скидка действует только на одну; остальные продаются с обычной наценкой. Комиссии платежей остаются расходом магазина.
- Каталог, карточка и подтверждение показывают цену с учётом купона. При изменении закупочной цены или использовании купона в другом заказе требуется новое подтверждение суммы.
- Лимит активаций, использование купона и списание баланса защищены транзакциями. Нехватка баланса и отсутствие товара не тратят купон. При подтверждённом отказе поставщика возвращаются деньги и купон; при неизвестном результате они остаются за заказом до выяснения.
- `/promo_stats КОД` показывает выданные купоны, успешные покупки и заказы на проверке. `/promo_disable КОД` останавливает только новые активации; уже выданные купоны сохраняются. Повторное создание существующего кода не сбрасывает лимит.
- Таблицы `catalog_promotions` и `catalog_promotion_claims` создаются при запуске через существующий `init_db`; прежние балансы и заказы сохраняются.

### Заказы каталога (синхронные)
1. Проверка баланса → списание → вызов API → выдача ключа
2. При ошибке API — автоматический возврат средств

### Прямая оплата поставщику без предварительного пополнения магазина

Для одной покупки по купону без наценки (например, `GEMINI100`) подтверждение содержит кнопку «Оплатить криптой напрямую». Покупатель оплачивает счёт поставщика в CryptoBot; средства поступают на партнёрский счёт, затем бот закупает и выдаёт товар. Внутренний баланс покупателя не начисляется и не списывается. Обычные покупки с наценкой сохраняют оплату с внутреннего баланса: автоматического разделения наценки поставщик не предоставляет в проверенном API.

- Наличие и цена проверяются перед созданием счёта и перед закупкой. Если товара нет, счёт не создаётся. Поставщик не резервирует товар на время оплаты через этот API.
- Счёт и заказ сохраняются в SQLite до обращения к API. Депозит привязан к конкретному заказу и покупателю; статус, ID, сумма и метод платежа проверяются через API поставщика. Запрос создания счёта/закупки при потерянном ответе автоматически не повторяется.
- Счета находятся в истории и `/direct_orders`. Проверка оплаты идёт автоматически каждые 15 секунд; есть кнопка ручной проверки. Выданные данные доступны повторно только владельцу заказа, длинные данные — файлом.
- Средства открытых счетов защищены от обычных закупок магазина. Все расходы через бот используют общую блокировку и проверку защищённой суммы. Ручные операции в кабинете поставщика этой блокировкой не контролируются: не расходовать там средства покупателей, чьи заказы не завершены.
- При подтверждённой оплате и отсутствии товара/изменении цены заказ остаётся на проверке, деньги не превращаются в расходуемый баланс бота. Поддержка может повторить заведомо неудачную выдачу после восстановления наличия/цены.
- При неизвестном исходе закупки или прерывании процесса заказ замораживается для ручного выяснения. Бот никогда не делает вторую закупку такого заказа.
- Автоматического возврата в проверенном API нет. Возврат требует ручного решения с поставщиком; бот хранит обязательство перед покупателем и уведомляет поддержку. Это ограничение важно учесть перед рекламой.
- `DIRECT_SUPPLIER_CHECKOUT_ENABLED=false` отключает создание новых счетов и кнопку; уже созданные счета продолжают проверяться.

Администратор:
- `/direct_stats` — состояния счетов, их ID и защищённая сумма.
- `/direct_order ID_СЧЁТА` — подробности заказа и причина остановки.
- `/direct_retry ID_СЧЁТА` — повторная выдача только после подтверждённого отказа. Неопределённую закупку не повторяет.
- `/direct_refunded ID_СЧЁТА СУММА ВОЗВРАТ_ВЫПОЛНЕН` — отметить возврат, **уже выполненный вручную**. Эта команда не переводит деньги, восстанавливает купон и снимает внутреннюю защиту суммы только после утверждения администратора о возврате.

Проверенный ответ статуса депозита содержит `deposit_id`, `amount` (рубли), `method`, `status`. Он отличается от ответа создания счёта с `amount_rub`, `amount_usdt`, `pay_url`; модели разделены. Таблица `supplier_checkouts` создаётся при запуске без изменения прежних балансов.

### Внешние заказы (асинхронные)
1. Steam / Игры → заказ уходит в `processing`
2. Фоновый polling каждые 15 сек проверяет статус
3. `success` → уведомление пользователю
4. `failed` → возврат на баланс + уведомление
5. `uncertain` → заморозка средств + алерт админу

### Безопасность
- API-ключ только в `.env`
- Rate-limit 8 req/s (ниже серверного 10)
- Ретраи с exponential backoff на 429 и 5xx
- Транзакции БД: списание + заказ атомарно
- Валидация всего ввода пользователей
